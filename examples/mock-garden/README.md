# Fictional Mindgarden sandbox

This is a persistent example garden built with the real engine. Every person,
business, account, transaction and conversation is invented. It gives the next
freshness/summary/import checkpoints a shared dataset without needing personal
records or credentials.

From a source checkout on the supported private POSIX filesystem baseline:

```sh
python -S scripts/mock_garden_demo.py \
  --workspace /var/tmp/new-fictional-mindgarden --require-source --check-golden
```

Choose a new or empty owned mode-0700 directory outside Git, using a canonical
path without symlinks. The command retains the generated garden for exploration,
refuses existing content, and never edits a real registry or discovers an account.
On completion, open `START-HERE.md` in that directory. Its copyable commands use
the exact source/installed engine and private bindings/session created for this
instance. It is local machine-specific guidance, outside portable records.

## Contents

- The existing synthetic ledger: two supplied accounts, eight unique transactions,
  an overlapping export, a reviewed transfer, an uncategorized payment, a missing
  account and coverage gaps. These are movements, not balances or full history.
- A fictional one-person business and portfolio project.
- A fictional career/accessibility learning plan and household spending questions.
- An authored Markdown client conversation with speaker attribution, conflicting
  delivery dates and deliberately hostile quoted instructions retained as data.
- Explicit authored fixture summaries, exact evidence, related links and a typed
  contradiction. Fixture approval is artificial; it is not a real user's review.
- An existing private preparation packet, a bounded context and working
  search/graph/evidence commands, with no model or real Google request.
- A later business correction in `staged-changes/`, deliberately not imported or
  reviewed. It is input for future #37/#46 work, not a silently applied update.

The [world manifest](world.json) binds every source file's checksum and the authored
summary/review selections. The original ledger/capture data remains in the
existing consultation/Drive fixtures; it is not duplicated into another engine.
Source records stay unreviewed and source instructions grant no authority.

## Where to look

| Generated path | Purpose |
| --- | --- |
| `START-HERE.md`, `commands.json` | Local entrypoint and exact runnable commands |
| `clean-garden/.garden/` | The active portable garden, selected by the local bindings |
| `restored-vault/` | Immutable evidence in the existing filesystem vault |
| `clean-bindings.json`, `mock-session.json` | Machine-local locations and fresh explicit authority |
| `mock-inputs/`, `mock-curation.json` | Exact fictional sources and authored curation proposal |
| `mock-context.json`, `mock-packet/packet.md` | Bounded context and selected financial report |
| `staged-changes/` | Unapplied fictional correction |
| `proof.json` | The underlying capture/review/research/relocation/restore/rebuild proof |

The earlier proof gardens, sessions, captures and packets are retained. Use the
active bindings and **mock-session.json** after the added notes; an earlier session
does not become fresh merely because it still exists. The financial packet selects
its eight exact ledger rows and excludes the new business/career/household notes.

The launcher uses ordinary ingestion, authored curation plan/apply, scoped
retrieval, exact evidence and packet services. It performs the predetermined
fictional fixture reviews, blocks network/HTTP/external process calls, and leaves
the normal Python/v0 CLI untouched. No web app, automatic summary generation,
live Drive/Codex, bank-format compatibility or private-pilot acceptance is claimed.

Current launch/preflight filesystem controls are POSIX-only. Native Windows and
real confidential processing retain their separate contracts. The source/wheel/
archive evidence and remaining scope are recorded in the repository handoff.
